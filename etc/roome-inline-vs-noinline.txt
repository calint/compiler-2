roome.baz: inline against noinline, instruction counts per machine
--------------------------------------------------------------------------------
taken 2026-10-06 with the 'instructions:' line of the footer of the generated
assembly, a noinline body is counted once. 'text' is the code section of the
nasm object (x86_64), rv32i instructions are 4 bytes each.
the output of every variant was compared with etc/roome/roome.out on rv32i-fpga
(emulator) and on x86_64 (native), all are the same.

variants of etc/roome/roome.baz
  as written   'entity.find_object' and 'parse_input' are noinline, the other
               functions are inlined
  all inline   'noinline' removed from those two
  all noinline every function except 'main' is 'noinline' (generic methods and
               methods included)

reading
--------------------------------------------------------------------------------
1. all noinline is not better than as written: 130% (x86_64) and 112%
   (rv32i) more instructions with no checks. not analysed, the generated code
   of a call writes frame slots and saves registers, and a result or an
   argument without storage goes through a temporary of the caller.
2. all noinline against all inline, no checks: 30% more instructions on x86_64
   and 17% more on rv32i, but 10% fewer code bytes on x86_64 (inline code is
   longer per instruction: more memory operands and immediates). on rv32i all
   instructions are 4 bytes, so inline is smaller there (36532 against 31300).
3. with noub,line all noinline grows the most (14238 against 10677 on rv32i),
   the 'frame' check of 'noub' applies to calls of noinline functions only.
4. the best size is the mix as written: the two functions that unfold into a
   lot of code and have 2 callers are noinline, the small ones are inlined.
5. speed was not measured, only code size.
