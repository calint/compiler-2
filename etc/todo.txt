[p] hard: constants: one system for values known at compile time (plan
    2026-10-21, waits for go-ahead; aliasing follows as its own plan)
    => problem: seven evaluators of a constant ('folded_constant' and its
       overrides, 'constant_value_of'/'constant_wrap', 'side_constant'/
       'typed_constant', 'element_constant'/'arith_constant', the convert
       'constant_value'/'narrow', 'make_constant_operand', the 'stmt_call'
       alias folds), each with its own answer to typedness, fit, where unary
       ops apply and overflow; the overflow check is toggled on 'toc'
       (pause and resume); verdicts differ by spelling: G6-1, G6-2, G6-3,
       G4-1, G5-1, ARCH-6, G5-2, 'array_length' typed in an assignment and
       untyped in a comparison
    => the system, one rule per function:
       1. a constant is a variable whose value is known: a typed constant
          (a conversion, a constant argument of an inlined call,
          'array_length') gets every verdict a variable of its type gets;
          an untyped one (a literal, a 'let') has no type and is checked by
          value where it is used
       2. a use is the width a value is computed at and whether its
          arithmetic is checked for overflow: 'value_use', built only by
          'toc::use_of(dst)' and 'toc::use_at(type)'
       3. one fit rule for a leaf: typed by type, untyped by value; every
          check (assignment, list element, comparison side, argument) calls
          it, only the messages differ
       4. one evaluator, the virtual 'fold(tc, use) ->
          std::optional<folded_value>': 'value' wrapped to the use width,
          'own_type' null when untyped; it checks fit before it wraps, so no
          fold is accepted unchecked; overrides: identifier, list,
          conversion, 'array_length', zero
       5. unary ops apply by 'unary_ops' on a register at least as wide as
          the use; the widths of a conversion are one struct
          'conversion_widths{converted, argument, ops}' that its fold and
          its compile share
       6. the overflow policy is a field of 'destination' ('as_wrapping()'
          for a conversion argument); 'toc::checks()' never changes
       7. a value in a numeric position has a built-in non-record type,
          checked at parse ('assert_number')
       8. emitters take 'fold(...)' and emit 'operand::imm(value, width)';
          nothing else evaluates
    => deleted: 'folded_constant', 'is_typed_constant' (4),
       'constant_value_of', 'constant_wrap', 'single_operand_type',
       'side_constant', 'typed_constant', 'make_constant_operand', the
       convert 'constant_value'/'narrow', the expr_bool
       'assert_constant_fits', 'overflow_check_pause'/'resume',
       'overflow_requested_'
    => rejected:
       1. a fix at each bug site: seven evaluators remain and drift again
       2. pause and resume narrowed to the call body: still state toggled at
          a distance that each new caller of a fold must know
       3. the overflow policy as a 'compile' parameter: about 40 overrides
          for 6 users; 'destination' already carries properties of the use
       4. a one-node IR evaluated or emitted: touches every emitter, while
          the rules diverge, not the evaluators
       5. a fold without the fit check, checked by callers: the contract
          that G5-1 broke
    => invariant: a typed constant and a variable of the same type and
       value give the same verdict and result; an overflow or zero divisor
       certain at compile time equals the run-time panic
    => steps, one diff each; R: byte-identical on the gate (all tests, the
       tutorial and roome, both targets, 7 option sets, stdout, stderr and

       R1 'folded_value', 'value_use' and 'fold' replace the evaluators,

       R2 delete 'single_operand_type' (G5-6)
