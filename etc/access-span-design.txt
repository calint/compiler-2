access_span: aliasing check of what is reached through run-time indexes
=======================================================================

source: src/ub_check.hpp ('access_span', 'path_step')
used by: stmt_assign_var.hpp, stmt_call.hpp (storage_target in toc.hpp)
built by: stmt_identifier.hpp, toc.hpp
          ('storage_target_of', 'scope_stack::root_span')
tests: 931-971 in qa/coverage/tests (970 and 971: a constant element and a
       field against a run-time indexed read)

1. Problem
----------

Two accesses to the same root variable alias when they can reach a common
byte. With a run-time index the byte is not known, so the check must answer
"can these ever be the same byte for some value of the indexes".

Answer false only when provably disjoint. Anything unknown is "may alias".

2. The path
-----------

An access is the path from its root variable: one 'path_step' per field,
constant index or run-time index. The root variable itself is not a step.

    path_step { kind, number }

    kind                number
    field               offset of the field in its parent
    fixed_index         the index
    run_time_index      unused

    rooms[i].items[1].name

    steps:  index (run-time)  field 'items'  index (constant 1)  field 'name'

An index always follows a field or the root variable. Both paths of a
comparison start at the same root variable and follow the same types, so at
one position they are both fields or both indexes.

A field is identified by its offset in the parent. Fields never overlap (every
field has a size, a type has a field and an array has at least one element),
so different offsets are different fields.

3. overlaps(lhs, rhs)
---------------------

'overlaps' is 'not paths_diverge(lhs.path, rhs.path)'. The steps line up, walk
them together:

    run-time index on either side             => go on, may be the same
    field, different offset in the parent     => disjoint
    constant indexes, different               => disjoint
    same field (same offset) or same index    => go on
    paths ran out                             => may alias (one is inside the
                                                 other, or they are the same)

examples

    'items[i].id' and 'items[j].name'
        different fields                                  => disjoint
    'items[i].name' and 'items[j].name'
        same field, run-time index                        => may alias
    'es[1].items[i].f' and 'es[k].other'
        [1] and [k] go on, 'items' and 'other' differ     => disjoint
    'arr[1]' and 'arr[2]'
        different constant indexes                        => disjoint
    'arr[1]' and 'arr[i]'
        run-time index                                    => may alias
    'es' and 'es[i].other'
        the first path ran out                            => may alias

No bytes are compared, so there are no periods, slots or alignment to line up
and a constant index in the middle of a path does not lose information.

4. Building spans
-----------------

An identifier adds a step per path element ('stmt_identifier::
resolve_access_range'):

    add_field(offset)        '.name'
    add_fixed_index(index)   '[3]', an index known at compile time
    add_run_time_index()     '[i]'

An alias (a parameter, a result, the element 'e' of a 'foo') is bound to the
span of what it names; an access through it joins the paths:

    narrow_to(inner)         the path of the bound target followed by the path
                             of the access inside it
    add_run_time_index()     'e' of a 'foo' is any element of the array

A target whose span is not known has no span, which is the whole variable and
always may alias.

5. Bytes: not part of this check
--------------------------------

The compiler also rejects reading a variable before it is set, and a
constructor that does not assign every field. For that it records which bytes
of a variable are assigned, and a read must be inside them, so it needs bytes,
not a path. 'stmt_identifier' keeps the bytes of its path in 'access_range_'
and the path in 'access_span_', and the read visitor receives both
('read_visitor': the range for the uninitialized read check, the span for the
aliasing check).

    type item { id i32, name i64 }
    var it = item
    it.id = 1            assigns bytes 0..4
    x = it.name          reads bytes 4..12, not assigned => error

The root variable is the whole variable, each field and each constant index
narrows it ('stmt_identifier::narrow_access_range'). After a run-time index
the element is unknown, so the range stays the whole array: a write through
'arr[i]' assigns nothing and a read through it needs the whole array.
'access_span' holds only the path.
