roome.baz on x86_64: local inefficiencies within one machine operation
--------------------------------------------------------------------------------
compiled with: ./baz --target=x86_64 --vars=0x20000 --checks=noub,line \
                     etc/roome/roome.baz
3941 instructions (2026-10-06, the counts of the points below were taken
before 'roome.baz' shrank, they are kept as history). global optimizations and
instruction tricks excluded. site counts are occurrences in the generated
code. the rv32i report is etc/roome-inefficiencies-rv32i.txt, points that
exist on both targets keep their rv32i number in brackets.

[x] 1. redundant sign test in check_bounds [rv32i 2] (224 index sites, 110
       count-only sites, 3 instructions each with line numbers on)
       'test r,r; cmovs; js' before a signed 'cmp r,N; cmovge; jge'.
       with both checks on and no count register the upper compare is now
       unsigned ('cmovae/jae', 'cmova/ja' when the end is allowed), which
       fails a negative value too, as long as the limit is below
       2^(width - 1). the omission is commented in the assembly.
       where: check_bounds

[x] 2. count tested again for the second array [rv32i 3]
       the sum form 'index + count' tested the count in every call, the
       second array of array_copy or arrays_equal repeated it. a bitmask,
       'lower_checked_registers_', remembers registers a lower check found
       non-negative and is cleared when the register is allocated again.
       where: check_bounds, push_allocation
       roome 9328 -> 8134 instructions with point 1

[x] 3. 'mov r12,rcx; add r12,r14; cmp r12,127' for the range end (213 sites,
       1 instruction each)
       'lea r12,[rcx + r14]' computes the sum in one instruction, when both
       registers are qwords (narrower ones keep the widening 'mov'). roome
       8134 -> 7921 instructions.
       where: compare_upper_bound

[x] 4. bounds failure plumbing: 547 checks cost 547 'mov reg,line' and 909
       'cmovcc rbp,reg', 1456 instructions (about 19% of the 7790 counted
       instructions of the program)
       each check loaded the line number into a scratch register and every
       condition did 'cmovcc rbp,line; jcc panic' so rbp, the variables
       base, survived when the check passed. two effects:
       - a sum check had three conditions and three cmovs, 12 instructions.
       - rbp was written by the cmov, so every memory access after a check
         waited on the compare, a dependency a predicted branch does not
         create.
       now every condition is 'jcc baz_bounds_line_N' and each distinct
       line has one out-of-line stub in the handler section, 'mov rbp,N;
       jmp baz_bounds_panic', so a passing check runs only its compare and
       branch: 'cmp r15,81; jae baz_bounds_line_1016'.
       roome 7790 -> 6515 instructions counted, 91 stubs.
       rv32i keeps its '1:'/'2:' block: conditional branches reach only
       4 KiB, so stubs far away need far jump resolution.
       where: check_bounds, branch_to_bounds_panic, emit_bounds_failure_handler

[ ] 5. run-time count compare uses only 'repe cmpsb' (42 sites, 18 now)
       'repe cmps*' is microcoded and costs about the same per element at
       every width, so a qword split pays for long arrays only. it needs
       about 7 more instructions and a scratch register, and loses for the
       short names roome compares. not done, a length-gated qword loop is
       the version to write if long run-time arrays show up.
       where: end_arrays_equal

[ ] 6. 'lea rsi,[base + disp]; add rsi,start' for the address of write [rv32i
       9] (about 70 of 80 sites, 1 instruction each)
       'lea rsi,[rbp + 879]; add rsi,r15' is 'lea rsi,[rbp + r15 + 879]'. the
       10 sites whose address already has an index register keep the 'add'.
       about 74 sites have the constant 'start' 0, there the 'add' goes away
       with the 'mov r,0; test r,r; js' checks, see 'not counted'.
       where: write

[ ] 7. fixed-size array compare stores a bool and tests it [rv32i 8] (2
       sites, 2 instructions each)
       'repe cmpsq; sete r9b; cmp r9b,0; je else' is 'repe cmpsq; jne else'.
       the other 18 sites store the result for a bool 'and', 'sete' is needed.
       where: memory_equal

not applicable on x86_64, the rv32i point does not exist here:
- rv32i 1 base address computed twice: one memory operand is addressed
  [rbp + disp32], there is no 'lui/add' pair
- rv32i 4 bulk loop bookkeeping and 5 '.Lbaz_write': copy, zero and compare
  use 'rep movsb/stosb/cmps*', writes are syscalls
- rv32i 6 equality in a bool 'and': 'cmp; sete; jne' is already minimal
- rv32i 7 bounds failure code inline: done here, point 4

not counted, they need a known constant:
- 'mov rcx,imm; test rcx,rcx; repe cmpsb' where the count is known to be
  nonzero (42 sites)

fixed outside the numbered points: 'mov r,imm; cmp x,r' for a constant right
side such as 'array_length(...)' (30 sites), the length is now an immediate

instruction tricks, excluded:
- 'xor edi,edi' for 'mov rdi,0', 'mov r,0' (145 sites) as 'xor'
- 'test r,r' for 'cmp r,0' ('cmp r15b,0' 68 sites)
- 'imul r,960' by a constant as 'lea/shl' chains
- both sign tests of a sum check as 'mov t,index; or t,count; js' (2
  instructions less per sum check)

not inefficiencies:
- 'mov r,[mem]; mov [mem2],r' (234 sites) there is no memory to memory move
